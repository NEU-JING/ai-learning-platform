## 验收场景

### AC1: 完成学习行为获得 XP

- **Given** 登录用户处于课程学习中
- **When** 用户完成一个 Lab 且评分通过
- **Then** 用户获得该 Lab 对应的 XP，累计 XP 增加，系统记录 XP 明细

### AC2: XP 按行为粒度不重复计（幂等）

- **Given** 用户已完成某 Lab 并获得 XP
- **When** 同一 Lab 被再次提交（重试/重做）
- **Then** 不会重复发放该 Lab 的 XP（以首次通过为准）

### AC3: 累计 XP 触发升级

- **Given** 用户累计 XP 达到某等级门槛
- **When** 系统检测到 XP 增加后跨越门槛
- **Then** 用户等级提升，系统记录升级事件，前端展示新等级

### AC4: 达成条件自动发放徽章

- **Given** 系统定义了里程碑徽章（如"首个 Lab 通关"、"连续学习 7 天"、"任务链完成者"）
- **When** 用户行为满足徽章发放条件
- **Then** 徽章自动授予用户，发放记录持久化，可在徽章墙查看

### AC5: 每日挑战

- **Given** 当天存在一个已发布的每日挑战任务
- **When** 用户提交并评分通过
- **Then** 用户获得挑战双倍 XP，打卡成功，连续天数（streak）+1

### AC6: 每日挑战未完成/超时（异常路径）

- **Given** 用户当天未提交或提交未通过每日挑战
- **When** 一天结束
- **Then** streak 计数归零（不记录新打卡），不发放挑战 XP

### AC7: 领取一个任务链

- **Given** 用户已具备领取条件且任务链处于 active 状态
- **When** 用户开始一个任务链
- **Then** 系统记录任务链启动，展示链内第 1 个任务

### AC8: 完成任务链中的单个任务

- **Given** 任务链已启动，当前是第 N 个任务
- **When** 用户提交代码并在沙箱执行
- **Then** 系统自动评分：通过则记录 score+output+耗时，解锁下一个任务；失败则给出提示，可重试

### AC9: 完成整个任务链（证据卡生成）

- **Given** 任务链内所有任务均已通过
- **When** 最后一个任务通过
- **Then** 任务链标记为完成，自动生成一张证据卡（聚合各任务分值、运行结果、耗时、时间戳），用户零整理即可查看

### AC10: L1 认证自动发证（Lab 路径）

- **Given** 用户完成了某认证等级必修模块的全部 Lab 且通过
- **When** Lab 通过记录被系统检测到满足发证条件
- **Then** 系统自动为该用户签发对应等级的认证，无需用户手动申请，且只签一次（幂等）

### AC11: L1 认证自动发证（任务链路径）

- **Given** 用户完成了某认证等级关联的任务链
- **When** 任务链完成事件被系统检测到满足发证条件
- **Then** 系统自动签发对应等级认证，幂等

### AC12: 认证已存在时不重复签发（幂等边界）

- **Given** 用户已持有某等级认证
- **When** 再次触发同一等级的自动发证条件
- **Then** 不再签发新认证，现有认证保持不变（create_only 语义）

### AC13: 模块内容更新不影响已发认证（边界条件）

- **Given** 用户已获得某等级认证，之后课程/任务链内容变更
- **When** 内容更新完成
- **Then** 已发认证不撤销、不降级（仅对新学习者按新条件评估）

### AC14: 未满足发证条件时不发证（异常路径）

- **Given** 用户只完成了模块部分 Lab（未全通过）
- **When** 系统评估发证条件
- **Then** 不签发认证，用户可查看缺哪些 Lab/任务才能获得

## 业务规则

| 规则编号 | 规则描述 | 涉及场景 |
|:---:|------|:---:|
| BR1 | XP 以"首次通过"为发放基准，重复不发放 | AC2 |
| BR2 | 游戏化只增不减：不扣 XP、不降级、无惩罚 | AC3, AC6 |
| BR3 | 认证自动发证 = 满足条件即发，零人工干预 | AC10-AC13 |
| BR4 | 认证幂等且不被内容更新撤销（create_only） | AC12, AC13 |
| BR5 | 证据来自沙箱真实执行记录，系统不提供任何人工作假或评分入口 | AC8, AC9 |

---

## 边界条件

| 边界 | 条件 | 预期行为 | 涉及场景 |
|------|------|---------|:---:|
| 重复提交 | 同一 Lab/任务反复提交 | 只按首次通过发 XP | AC2 |
| streak 归零 | 某天未完成每日挑战 | streak 清零 | AC6 |
| 认证重复 | 已持证再触发发证 | 不重复签发 | AC12 |
| 内容变更 | 课程/任务链更新 | 已发认证保留 | AC13 |
| 部分完成 | Lab 未全过 | 不发证，提示缺口 | AC14 |

---

## 错误场景与用户提示文案

| 错误场景 | 触发条件 | 用户看到的提示文案 |
|---------|---------|-----------------|
| 任务提交评分失败 | 沙箱执行超时/异常 | "执行超时，请重试或检查代码" |
| 认证缺口 | 未满足全部 Lab/任务 | "还差 N 个实验/任务即可获得该认证" |
| 任务链不可用 | 任务链非 active | "该任务链暂未开放" |

## 关键非功能需求

| 需求类型 | 要求 | 衡量方式 |
|---------|------|:---:|
| 性能 | XP/徽章发放与升级判定 ≤ 200ms（同步内完成） | 请求耗时统计 |
| 安全 | XP/认证发放仅服务端判定，客户端不可伪造 | 变更均经服务端校验 |
| 可用性 | 评分/发证失败不阻塞学习流程（先出结果，补偿后置） | 单测 + 异常注入 |
| 一致性 | 并发下 XP 幂等、认证唯一 | 并发测试 |

# F6 补充：技能成长趋势（技能趋势图，P1）

## 验收场景

### F6-AC1: 有学习事件 → 返回按时间聚合的技能分数变化

- **Given** 用户在多个时间点完成了不同技能维度的 Lab（SkillEvent 自动记录）
- **When** 查询技能趋势
- **Then** 返回从旧到新的多个时间桶，每个桶含各技能维度分数，呈现分数随时间变化

### F6-AC2: 分数时间衰减生效

- **Given** 同一维度有早期和近期事件
- **When** 计算各时间桶分数
- **Then** 近期事件权重更高，早期事件分数随时间衰减，曲线反映真实成长而非瞬时波动

### F6-AC3: 无事件用户 → 空趋势

- **Given** 用户从未产生任何技能事件
- **When** 查询技能趋势
- **Then** 返回空列表或全 0 分数（前端显示"开始学习即可看到成长"引导，不报错）

### F6-AC4: 前端成长可视化（零操作）

- **Given** 用户有学习记录
- **When** 打开进度页/个人页
- **Then** 自动展示技能成长曲线，用户无需手动记录任何数据（证据来自行为，零负担）

## 业务规则

| 规则编号 | 规则描述 | 涉及场景 |
|:---:|------|:---:|
| BR-F6-1 | 趋势数据源 = SkillEvent（行为自动记录），不要求用户手动打点 | F6-AC1, F6-AC4 |
| BR-F6-2 | 时间衰减与现行 skill score 计算一致（90 天半衰期） | F6-AC2 |
| BR-F6-3 | 空数据返回空趋势 + 引导文案，不视为错误 | F6-AC3 |

## 边界条件

| 边界 | 条件 | 预期行为 | 涉及场景 |
|------|------|---------|:---:|
| 无事件 | 用户 0 事件 | 空列表，前端引导 | F6-AC3 |
| 单维度 | 只学一个维度 | 展示单个维度曲线 | F6-AC1 |
| 时间跨度 | 事件跨多周 | 按周桶聚合，跨周对比 | F6-AC1 |

## 关键非功能需求

| 需求类型 | 要求 | 衡量方式 |
|---------|------|:---:|
| 性能 | 趋势查询 ≤ 500ms | 请求耗时 |
| 一致性 | 与当前雷达分数语义一致（同一衰减模型） | 对比当前 score |
