## 0. 设计原则（v1.1 核心变更）

> **验证是学习过程的自然副产品，不是用户要额外做的事。**

v1.0 设计把 Capstone 做成"用户照模板写内容提交"，学习负担重、体验灾难。**已废弃**。

新原则：
1. **证据来自行为，不来自表单**——用户做任务/打挑战/对话，系统自动收集证据，用户**零整理负担**
2. **短循环激发动机**——XP、徽章、每日挑战让学习像游戏，愿意学
3. **长循环保证可信**——任务链通过即时自动评分验证，高分项可抽检人工复核，防作弊

```
短循环  游戏化（XP/徽章/每日挑战）      → 有趣、愿意学
中循环  任务链（渐进小任务 + 自动评分）  → 快速掌握
长循环  证据自动沉淀（行为全入库）       → 零负担、可验证
```

## 1. 背景

Phase 1-3 交付了 "Lab 判题 → 证书" 链路，但存在三个缺口：

| 缺口 | 现象 | 后果 |
|------|------|------|
| **动机缺口** | 学习是线性任务列表，无即时激励 | 完课率低、弃学率高 |
| **深度验证缺口** | 预设用例判题只能证明"会做题" | 无法证明"会做项目"，认证含金量不足 |
| **证据零散** | 对话、挑战、项目无关联 | 雇主看不到能力成长轨迹 |

## 2. 目标

1. **激发持续学习**：引入游戏化机制（XP/徽章/每日挑战），完课率提升
2. **深度验证轻量化**：任务链式 Capstone 替代模板提交，用户 5-15 分钟/任务、即时反馈
3. **证据自动沉淀**：所有学习行为自动入库成证据，零用户负担，可追溯可审计

## 3. 目标用户

| 用户角色 | 特征 | 核心诉求 |
|---------|------|---------|
| 学习者 | 完成模块 Lab 的学员 | 学得爽、有反馈、有成就感 |
| 深度用户 | 想挑战真实问题的学员 | 有舞台练真本事，但不想写文档 |
| 持续学习者 | 长期在平台刷能力的人 | 打卡、成长曲线、看得见的进步 |

## 4. 核心功能点

### F1: 游戏化引擎（P0）—— 有趣、愿意学

- **XP 系统**：完成 Lab/任务/挑战 → XP；累计 XP → 等级（等级门槛配徽章）
  - 数据：`xp_events`（明细，谁/什么行为/多少 XP/时间）+ `user_xp`（累计）
- **徽章系统**：里程碑徽章（首个 Lab、连续学习 7 天、挑战达人、任务链完成者等）；徽章定义可配置
- **每日挑战（Daily Challenge）**：每天 1 个 10 分钟小任务，完成得双倍 XP + 打卡记录（streak 连续天数）
- **进度可视化**：等级进度条 + 徽章墙（个人页）；排行榜（P1，先不做）
- 约束：游戏化只做激励与成就感展示，**不做付费门槛、不做惩罚机制**（不扣 XP、不降级）

### F2: 任务链 Capstone（P0）—— 快速掌握、零负担

替代"模板文档提交"的深度验证：

- **任务链结构**：一个 Capstone = 1 个主题 + 3-5 个渐进小任务（每任务 5-15 分钟）
  - 任务类型：写函数/跑通脚本/修正 bug/小模型训练跑通/配置完成（复用 sandbox 执行）
  - 每个任务 = 场景描述（2-3 句，讲"为什么做"）+ 产出要求（可运行的成果物）+ 自动评分（grader 扩展/自定义评分器）
- **即时反馈**：提交 → 自动评分 → 通过/不通过 + 提示，马上知道对错
- **证据卡自动生成**：任务链完成 → 系统自动聚合（代码片段、运行结果、各任务评分、耗时、时间戳）成一张项目证据卡，**用户零整理，零人工评审**
- **信任来源**：证据即沙箱真实执行记录（代码跑过、结果可复现），行为级可信——**不设人工抽检/评审池**（YAGNI：MVP 阶段无作弊规模问题，上线后 analytics 出现信号再补机制）

### F3: L1 认证自动化（P0）—— 扩展触发条件

- **触发**：完成指定模块全部 Lab **或** 完成对应任务链 → 自动发 L1 证书（二选一路径，满足其一即发）
- **幂等**：已发不重复发；内容变更不撤销（create_only 语义）
- **证据**：证书记录关联 Lab/任务链通过列表 + 时间戳
- **通知**：发证写入 analytics 事件（certificate_issued），前端学习页/徽章墙展示

### F4: 场景挑战（P1）—— 任务链的进阶形态

- 模糊需求（无完整规格）+ 时间压力（倒计时）+ 真实数据
- 评分偏结果导向（跑通 + 达标指标），复用 grader/sandbox
- 产出进入证据卡（挑战记录：通过/耗时/指标）

### F5: AI 导师对话记录入库（P1）—— 行为即证据

- Tutor 对话结构化落库（user_id、会话、角色、内容摘要、时间戳、关联 lab/task）
- 作为学习过程证据 + 后续趋势分析素材；隐私字段脱敏（呼应 AC44）

### F6: 技能趋势图（P1）—— 成长可见

- 后端：技能趋势 API（基于 `user_skill_snapshots` 按周聚合）
- 前端：雷达图时间轴对比（个人页 + 公开主页）
- 数据源：复用现有 snapshot 写入点，不新建采集链路

## 6. 数据模型（新增）

```sql
-- 游戏化
xp_events(id, user_id, action, xp, created_at)          -- XP 明细（幂等：同一 action+user+ref 不重复计）
user_xp(user_id PK, total_xp, level, updated_at)        -- 累计与等级
badges(id, code UNIQUE, name, description, icon, criteria_json)   -- 徽章定义
user_badges(user_id, badge_id, awarded_at, ref_id)      -- 发放记录（create_only）

-- 任务链
capstone_chains(id, code UNIQUE, title, description, skill_tags JSON, is_active)
capstone_tasks(id, chain_id FK, seq, title, scenario, grader_ref, pass_threshold, xp_reward)
capstone_attempts(id, task_id FK, user_id, status, score, output, started_at, completed_at)  -- 提交/评分（沙箱执行记录即证据）

-- 挑战（v1.0 的 capstone_projects/capstone_submissions 表设计废弃；无人工评审表）
challenge_attempts(id, challenge_id FK, user_id, status, metrics JSON, started_at, completed_at)
```

## 7. 技术约束（继承项目红线）

- **数据契约**：Phase 3-6 `create_only`（新表定义通过数据契约断言 + 16 项契约测试）
- **Pydantic Schema 唯一真相源**：前后端字段名一致；改 schema 同步前端
- **TDD 强制**：每模块先写测试（红→绿→重构）
- **前端修改必冒烟**：涉及 frontend/ 的任何改动跑 Playwright 冒烟
- **编码后三阶段评审**：commit 前 post-coding-review
- **评分器扩展**：grader.py 增加"任务链评分器"注册机制（按 grader_ref 路由），不硬编码

## 8. 成功指标

| 指标 | 目标值 | 衡量方式 |
|------|:---:|------|
| 周活跃学习率（每日挑战参与率） | ≥ 50% | 挑战参与 / 活跃用户 |
| 任务链完成率 | ≥ 60% | 完成链 / 启动链 |
| L1 自动化发证覆盖率 | 100% | 审计：发证全自动 |
| 用户零整理负担 | 100% | 证据卡全自动生成，无手动上传入口 |

- **不做** 排行榜（P1 后置）、付费门槛、惩罚性机制（扣 XP/降级）
