## 1. 功能概述

将 AILP 从学习平台重构为 AI 能力验证平台，核心交付：
- 四级认证体系（L1-L4）
- 多维技能雷达
- 公开能力主页
- 混合执行沙箱（Layer A/B/C）
- 雇主验证 API

---

## 2. 详细需求

### R1: 四路径课程矩阵

**描述**: 根据用户目标角色，提供四种差异化学习路径

**输入**: 用户选择的目标角色（AI专家/AI工程师/AI应用者/AI管理者）

**输出**: 对应路径的课程序列、周期、能力要求

**约束**:
- AI专家路径：20周，覆盖P1-P6全部课程
- AI工程师路径：14周，侧重工程实现
- AI应用者路径：8周，侧重场景应用
- AI管理者路径：6周，侧重战略管理

### R2: 四级认证体系

**描述**: 建立从L1到L4的能力验证等级，每级有明确的验证标准和证据要求

**输入**: 用户学习数据、项目提交、考试成绩

**输出**: 认证状态、证书、验证报告

**约束**:
- L1：完成指定实验，代码正确执行
- L2：完成Capstone项目，通过代码审查
- L3：完成场景挑战，通过架构评审
- L4：完成Agent-Driven项目，展示AI工程化能力

### R3: 技能雷达系统

**描述**: 基于用户学习行为数据，计算多维度能力评分

**输入**: 实验数据、代码提交、AI对话记录、项目产出

**输出**: 6+维度技能雷达图、成长趋势、同级对比

**约束**:
- 维度覆盖：编程思维、算法理解、AI协作、问题解决、工程实现等
- 基于可观测行为，非主观评价
- 支持时间维度趋势分析

### R4: 公开能力主页

**描述**: 用户可控的公开档案，展示能力数据和验证结果

**输入**: 用户授权、隐私设置

**输出**: 公开访问的能力主页（ailp.com/p/{username}）

**约束**:
- 用户可控制展示内容
- 提供可验证的认证链接
- 区分公众视图和雇主视图

### R5: 混合执行沙箱

**描述**: 支持三层执行模型，平衡安全性和资源可用性

**输入**: 用户代码、执行环境选择

**输出**: 执行结果、日志、评分

**约束**:
- Layer A：本地沙箱，资源受限，适合简单练习
- Layer B：外部资源（Colab/Kaggle），适合深度学习
- Layer C：验证引擎，适合模型审计

### R6: 雇主验证 API

**描述**: 提供可信的能力验证服务，支持雇主查询候选人认证

**输入**: 认证编号、授权码

**输出**: 认证状态、技能雷达摘要、学习数据（脱敏）

**约束**:
- 需用户授权
- 支持API Key限流
- 提供审计日志

## 5. 数据需求（抽象描述）

### 5.1 用户路径数据

**需求**: 系统需要存储用户选择的学习路径、进度、里程碑完成情况

**关键属性**: 目标角色、路径模板、课程进度、里程碑状态、预计完成时间

**约束**: 每个用户同时只能有一个活跃路径，支持路径切换

### 5.2 技能雷达数据

**需求**: 系统需要存储用户多维度技能分数和历史变化

**关键属性**: 用户ID、维度名称、分数、计算时间、数据来源

**约束**: 支持时间序列查询，可回溯历史版本

### 5.3 认证数据

**需求**: 系统需要存储用户认证申请、审核结果、证书信息

**关键属性**: 认证等级、申请时间、审核状态、证书编号、有效期

**约束**: 证书编号全局唯一，支持过期检查和续期

### 5.4 沙箱执行数据

**需求**: 系统需要存储代码执行记录、结果、日志

**关键属性**: 用户ID、实验ID、代码内容、执行结果、评分、日志

**约束**: 执行日志保留90天，支持审计查询

### 5.5 审计报告数据

**需求**: 系统需要生成可验证的认证审计报告

**关键属性**: 认证ID、证据链、时间戳、签名

**约束**: 报告不可篡改，支持公开验证

## 6. 接口需求（抽象描述）

### 6.1 路径管理接口

**需求**: 系统需要提供路径查询、进度更新、诊断评估能力

**输入**: 用户ID、路径选择、诊断答案

**输出**: 路径详情、进度百分比、能力评估报告

**约束**: 支持路径模板查询，诊断结果影响路径推荐

### 6.2 技能雷达接口

**需求**: 系统需要提供雷达数据查询、历史对比、趋势分析能力

**输入**: 用户ID、时间范围、对比版本

**输出**: 雷达分数、历史快照、趋势分析

**约束**: 支持雷达图渲染数据格式

### 6.3 认证接口

**需求**: 系统需要提供认证申请、审核、证书生成、验证能力

**输入**: 用户ID、认证等级、申请材料

**输出**: 申请状态、证书下载、验证结果

**约束**: 支持证书真伪验证，需用户授权

### 6.4 沙箱执行接口

**需求**: 系统需要提供代码提交、执行、评分能力

**输入**: 用户ID、实验ID、代码内容、执行环境选择

**输出**: 执行结果、评分、日志

**约束**: 支持多层执行环境，资源限制

### 6.5 雇主验证接口

**需求**: 系统需要提供认证查询、能力数据获取能力

**输入**: 认证编号、授权码、API Key

**输出**: 认证状态、技能摘要、审计报告（脱敏）

**约束**: 需用户授权，支持限流，审计日志完整
